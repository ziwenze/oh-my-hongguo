# Media 模块开发指导

> 生效目录：`src/main/media/`；同时遵守仓库根目录 `AGENTS.md`。
> 目标：在合法授权的媒体用例中，保持解析正确、网络访问受控和本地代理资源有界。

## 职责与边界

- `cencDecrypter.ts`：解析 MP4 box、样本表、CENC 元数据并对受支持的测试媒体执行解密。
- `decryptionServer.ts`：提供仅绑定 `127.0.0.1` 的本地媒体服务、流注册、请求处理、Range 响应、缓存及退出清理。
- `src/main/sdk/adapter.ts`：根据上游播放模型决定是否使用媒体代理；Renderer 不应持有原始内容密钥。
- `src/renderer/player/WebPlayerAdapter.ts`：消费最终媒体 URL、播放/seek/错误，不负责密钥或本地 HTTP 服务实现。

## 修改时必须保持的约束

1. **授权先于实现**：不得默认拥有第三方内容的解密或再分发权；不得新增绕过 DRM、订阅、权限、频控的策略。仅针对经授权的测试向量和明确允许的内容验证媒体能力。
2. **输入不可信**：MP4 box 的大小、偏移、计数、嵌套边界、sample 表、IV、子样本长度都必须校验；畸形媒体应可控报错，不可越界、超大内存分配或无声返回部分损坏文件。
3. **密码学正确性**：不得通过单纯的 Node `crypto` 往返测试宣称生产 `decryptCencMp4()` 正确。多子样本计数器、加密/明文区间、不同 IV/box 布局要以有标准答案的授权样本验证。
4. **代理仅本地且最小权限**：禁止绑定 `0.0.0.0`、透传任意外部 URL、暴露原始密钥；不要把短流 ID 当作无限期可复用的访问凭据。外部请求需审核来源/协议/重定向，防止 SSRF 或凭证泄漏。
5. **资源必须有界**：对上游请求设置超时、最大响应大小、并发及缓存字节预算；仅限制“最多几个 Buffer”不足以限制内存。报错、关闭、切集需回收缓存和 in-flight 状态。
6. **Range 必须正确**：严格解析单范围、合法起止和 suffix；对非法或越界范围返回 416，保持 `Content-Range` / `Content-Length` / 200 / 206 语义。当前代理是**整段取回处理后**再响应本地 Range，不要误称上游真正流式按需解密。
7. **日志安全**：不得输出 keyHex、完整上游带签名 URL、匿名凭据、解密后的受限内容或可复现的密钥材料；错误消息须脱敏。
8. **播放能力需实测**：请求成功、`playing` 事件、首帧与音画解码属于不同证据层级；不得仅凭 HEVC flag 断言目标 OS/设备支持某编码。

## 常见修改路径

- **MP4/CENC 解析问题**：复现媒体格式 → 定位 box/sample 边界 → 增加正确性与畸形向量测试 → 修改解密器 → 测试原样本和回归样本。
- **进度拖动/Range 问题**：核对浏览器 Range 请求 → 验证 200/206/416 与 Content-Range → 测试并发中断、重复请求和多文件内存上限。
- **代理/播放源问题**：先核对 Adapter 归一化与授权前提，再检查 URL 注册、缓存和 Renderer 的错误传播；不要让业务 Renderer 接收密钥。

## 相关测试与准出

- `tests/cencDecrypter.test.mjs`：生产解密函数真实结果、异常结构、边界条件；历史测试中有仅验证 AES-CTR 算法往返的样例，不能将其当作 MP4 全链路验证。
- `tests/electronSmoke.mjs`、`tests/packagedRuntimeSmoke.mjs`：授权本地媒体的播放、seek、真实窗口和打包应用行为。
- 修改代理或解密器时至少运行 `npm run typecheck && npm test && npm run build`；涉及渲染/包内资源时增加 GUI Smoke 与当前平台的打包运行测试。
- 不在默认 CI 内请求第三方受限真实视频。需要网络或物理设备的性能/编解码验证时明确记录环境与未覆盖项。
