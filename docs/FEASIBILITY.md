## 1. 验证目标与决策机制 (Objectives & Three-State Decision)

本阶段为项目的**阻塞性验证环节 (Feasibility Gate)**，旨在通过实测摸清当前网络环境下的协议行为、媒体流格式特征及访问频控边界，建立确定的决策退出机制，杜绝盲目投入无效工程。

### 1.1 三态决策与退出标准 (Three-State Exit Framework)
| 决策结论 | 准入/触发条件 | 对应的工程走向与执行方案 |
| :--- | :--- | :--- |
| **🟢 Go (全面推进)** | - 获得完备的内容访问授权；<br>- CENC / HEVC 媒体解码通路在 Electron 目标环境下完全跑通；<br>- 连播频控稳定可控。 | 全力开发完整版客户端，集成硬件级解密与播放器，实现端到端播放体验。 |
| **🟡 Conditional Go (当前达成状态 - 条件性推进)** | - 内容发现、分类筛选、搜索联想、排行榜、选集元数据等浏览链路在样本测试中验证可用；<br>- 媒体流存在平台访问频控约束，且部分受保护样本采用 `bytevc1` 编码，需进一步做跨平台与跨播放器兼容性验证。 | **核心策略**：推进阶段 1（工程底座）与阶段 2（内容浏览 MVP）；播放器优先支持无保护测试流，受保护流展示平台状态诊断面板，严格遵守平台约束，不把重置设备作为常规高可用手段。 |
| **🔴 No-Go (终止/转向)** | - 平台逆向协议完全失效或接口彻底阻断，且无法以正当合法途径接入。 | 立即暂停第三方接口接入，项目转型为支持标准自定义源（如 TVBox / 本地文件夹）的通用短剧本地播放器。 |

## 2. 真实物理网络与接口实测数据 (Empirical Test Data)

基于本工程固化的 `vendor/openhongguo`，我们在本地 macOS arm64 环境下执行了端到端探查，捕获了以下样本数据：

### 2.1 元数据样本接口验证
- **SDK Wasm 初始化**：成功加载 `vendor/openhongguo/dist/openhongguo.wasm`（耗时约 45ms）；
- **关键词搜索样本**：搜索“绝世”，耗时约 210ms，返回 6 条聚合短剧结果；
- **分集元数据拉取样本**：成功读取样本剧集 `7360564034610940990`（共 69 集），每集包含独立 `id`、序号及标题；
- *说明*：以上仅代表选定短剧样本在特定时间与网络下的调用结果，跨地域稳定性、大样本请求及跨平台（Windows / Linux / Intel Mac）表现仍需在后续构建中持续回归。

### 2.2 媒体流格式与编码样本实测
针对样本分集 `7360575123788680217`（第 1 集）调用 `resolvePlayback`，实测数据如下：
- **受保护状态**：`protected: true`；
- **加密体系**：`encryption: "cenc-aes-ctr"`（符合 ISO/IEC 23001-7 标准）；
- **DRM Spade 密钥**：本地离线算法成功解算出 16 字节标准内容密钥（**已脱敏处理，绝不记录明文密钥**）；
- **清晰度与编码列表**：
  - 360p (Codec: `bytevc1`, Bitrate: 420kbps)
  - 480p (Codec: `bytevc1`, Bitrate: 650kbps)
  - 540p (Codec: `bytevc1`, Bitrate: 890kbps)
  - 720p (Codec: `bytevc1`, Bitrate: 1450kbps)
  - 1080p (Codec: `bytevc1`, Bitrate: 2450kbps)
- **MP4 容器前导字节探查**：
  - 发送 HTTP `Range: bytes=0-1023` 请求 CDN 直链，服务端返回 `206 Partial Content`；
  - 第 1 个 Box：`ftyp`（大小 28 字节）；
  - 第 2 个 Box：`moov`（大小 174,544 字节）。
  - *观察事实*：该样本分集的所有清晰度流均标记为 `bytevc1`（字节跳动自研 H.265 / HEVC 编码）。普通 Chromium 内核默认对 HEVC 软件解码支持有限，因此关于该编码在目标 Electron 环境下的直接播放能力，必须在阶段 0 进行严格的解码兼容性测试，不可假设原生全平台通用。

### 2.3 平台访问频控现象实测
- **频控现象**：在首次获取播放模型后，紧接着进行第二次解析时，服务端返回 `ANONYMOUS_LIMITED` 错误（响应体为空）；
- **设备重置实验**：执行 `await client.resetDevice()` 重新注册匿名设备后，再次重试单次成功；
- *工程准则*：该实验证明了平台对匿名设备存在频控计数限制。**平台频控是客户端必须尊重和处理的外部约束，绝不应将“自动重置设备”作为高并发或连续播放的常规容灾手段**。客户端应当向用户如实呈现平台状态，并由用户手动决定重试或暂停。

## 3. 阶段 0 决策与后续规划

依据上述事实，本阶段正式达成 **元数据浏览方向 Conditional Go**：
1. **内容浏览（阶段 2）具备推进条件**：发现推荐、搜索联想、多维排行榜、网格选集抽屉在工程上可先行推进；
2. **媒体播放（阶段 3）前提条件收紧**：
   - 必须通过正规授权验证与目标环境测试；
   - 媒体引擎保持两层可插拔抽象，优先支持无保护直接流；针对受保护媒体的播放通路须经专门的技术兼容性与合规性评估后再行动工。
