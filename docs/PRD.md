## 1. 项目定位与合规边界 (Objectives & Compliance Boundaries)

### 1.1 项目定位
本项目是一款专为桌面平台（Windows / macOS）设计的短剧（微短剧）客户端交互实验项目。旨在利用桌面大屏、键盘快捷键、独立置顶小窗和自适应视窗，解决移动端短剧在桌面环境下黑边过大、操作繁琐、体验割裂的痛点。

### 1.2 严格区分“代码开源许可”与“内容访问授权” (P0-3 治理)
为确保项目合法合规，明确划分以下权利边界：
1. **软件代码许可**：本项目自主开发的代码以及引用的 `openhongguo` SDK 核心均遵循 **Apache License 2.0** 开源许可；
2. **内容访问与播放授权**：
   - Apache 2.0 许可证**仅覆盖本软件工程代码本身**；
   - **不代表、也不自动赋予任何第三方平台短剧音视频内容的观看权、解密权、商业使用权或离线分发权**；
   - 短剧元数据、剧照封面、音视频切片等资产的全部知识产权归原版权方及平台所有；
   - 本项目不提供任何集中式音视频存储、转码或 CDN 托管；
   - 软件明确保留“个人技术学习与逆向协议研究”属性，严禁用于任何商业牟利行为。

## 2. 核心架构升级：分层解耦与 Media Engine 抽象 (Architecture v1.1)

针对 v1.0 中“将未经充分验证的 Node.js AES-CTR Stream Proxy 作为唯一播放底座”的重大架构隐患（P0-1），v1.1 架构实施**分层解耦**，将媒体播放抽象为**可插拔的 Media Engine**。

即使底层媒体流访问方式或协议策略发生变动，应用层的发现、搜索、历史记录与窗口交互逻辑依然稳定，无需重构。

```
┌────────────────────────────────────────────────────────────────────────┐
│                        React 19 + TypeScript (UI 表现层)               │
│  - 页面路由 / 状态编排 (Zustand) / 键盘快捷键监听 / 触控板惯性过滤        │
│  - 视窗交互：竖屏自适应模式 (contain) / 宽屏剧场模式 / 独立置顶小窗     │
└────────────────────────────────────▲───────────────────────────────────┘
                                     │ Typed IPC / Preload Bridge (沙箱隔离)
┌────────────────────────────────────▼───────────────────────────────────┐
│                    Application Service (业务编排主进程)                │
│  - 剧集与播放会话管理 (Playback Session)                                │
│  - 错误与频控降级中心 (Rate Limit & Failure Handler)                   │
│  - 资源时效刷新调度器 (Expires-at Token Refresh)                       │
└───────────┬────────────────────────┬──────────────────────┬────────────┘
            │                        │                      │
            ▼                        ▼                      ▼
┌──────────────────────┐ ┌──────────────────────┐ ┌──────────────────────┐
│     SDK Adapter      │ │  Media Engine (插拔) │ │  Window & Storage    │
│  (vendor/openhongguo)│ │                      │ │                      │
│ - Wasm 匿名设备状态   │ │ 路径 A: 原生直接播放  │ │ - Window Manager     │
│ - 搜索 / 推荐 / 榜单 │ │ 路径 B: EME ClearKey │ │   (主窗自由缩放/小窗)│
│ - 选集 / 演员元数据   │ │ 路径 C: 外部硬解扩展 │ │ - Data Store         │
│ - DRM spade_a 密钥算 │ │ (通过阶段 0 决策门槛)│ │   (本地原子写入 JSON)│
└──────────────────────┘ └──────────────────────┘ └──────────────────────┘
```

### 2.1 模块职责划分
1. **UI 表现层 (React 19 + Tailwind CSS)**：纯粹的展示与交互，通过强类型的 `window.electronAPI` 与主进程通信，绝不直接接触 Node.js 原生 API。
2. **Application Service (主进程核心)**：统一调度业务逻辑，维护单实例播放会话（Single Playback Session），主窗口与置顶小窗共享同一会话状态。
3. **SDK Adapter**：对接 `vendor/openhongguo`，屏蔽底层 Wasm 细节，统一输出标准 Promise 数据对象，处理超时与脱敏。
4. **Media Engine (可插拔媒体引擎)**：定义标准媒体接口 `IMediaEngine`。根据不同的媒体流特征（未加密 MP4 / 加密 CENC / HLS / DASH），分派给经过可行性验证的适配器。
5. **Window Manager**：管理主窗口与独立置顶小窗，主窗口支持自由缩放（视频区域采用 `object-fit: contain`），小窗支持记忆尺寸与透明度。
6. **Data Store**：基于本地文件系统的原子化写入存储（Atomic Write + Debounce），管理历史记录、收藏夹与匿名设备档案。

## 3. 关键 P0 技术风险深入论证与应对策略

### 3.1 P0-1：CENC (Common Encryption) 媒体播放技术边界与论证
- **原设计缺陷**：认为可以把 CDN 加密 MP4 当成纯字节流，在 Node.js 中用 `crypto.createDecipheriv('aes-128-ctr')` 解密后直接 206 输出给浏览器。
- **事实与规范**：
  - ISO/IEC 23001-7 (CENC) 规范定义的是 **MP4 样本级加密**。MP4 文件的头部元数据 Box（`ftyp`, `moov`, `trak`, `stbl` 等）是明文；样本数据（Sample）内部可能包含明文头与密文负载（Subsample Encryption）；每个分片包含单独的 IV（初始化向量）与辅助加密信息（`senc` / `saio` / `saiz` box）。
  - 对整个 HTTP 字节流盲目进行 AES-CTR 解密会破坏 MP4 文件结构，导致浏览器解码器直接报错崩溃。
  - SDK 返回的流可能包含独立音频轨道（DASH 单独 `audio_url`）或 HLS (m3u8) 列表。
- **应对方案**：
  1. 播放能力不作为单一死板的前提，放入**阶段 0 可行性验证**实测；
  2. 针对受保护流，评估两条标准技术路径：
     - **路径 1（Web 标准 EME / ClearKey）**：使用支持 ClearKey 的现代 Web 播放器（如 Shaka Player / hls.js），将 SDK 导出的 16 字节 AES 内容密钥以 ClearKey 规范传入 EME 解码；
     - **路径 2（解复用重封装中继）**：若需中转，仅中转经授权测试流的样本解封装，或通过外部播放扩展模块（如 libmpv 绑定）进行硬件级解密；
  3. 未加密普通流与受保护流分流处理，清晰度由服务端实际返回的 `streams` 列表动态生成，不写死 1080p/720p。

### 3.2 P0-2：匿名设备播放频控与连续播放可用性
- **事实与现状**：自 2026-10-29 起，红果服务端对匿名 Guest 设备施加了严格频控，同一匿名设备通常仅返回一次可用播放模型，之后频繁返回 `ANONYMOUS_LIMITED` 错误；且新设备注册也不保证 100% 成功。
- **应对策略**：
  1. **坚决不实施“静默无休止轮换设备”**：禁止后台死循环调用 `resetDevice()`，避免触发平台更严厉的 IP 级风控封锁；
  2. **有限重试机制**：遇到 `ANONYMOUS_LIMITED` 时，仅允许受控重试 1 次（先重置设备档案再请求）；若仍然失败，立即向前端抛出明确状态；
  3. **明确的失败状态与用户诊断**：
     - 前端提供“内容暂不可用 / 平台访问频控”友好提示与一键重试按钮；
     - 增加设备健康度与诊断弹窗，明确向用户展示故障原因，保证体验确定性。

### 3.3 数据时效性治理 (CDN URL & Cover Expires)
- SDK 返回的 `cover_expires_at` 和 `expires_at` 均带有 UNIX 时间戳；
- 客户端**禁止持久化保存 CDN 完整直链**，本地历史记录与收藏夹仅持久化存储 `series_id`、`episode_id` 及时间戳；
- 每次进入播放页或封面展示时，判断时效性并在失效前异步重新换取有效地址。

## 4. 详细功能规范与交互体验设计 (v1.1)

### 4.1 视窗模式与短剧专属呈现
1. **竖屏沉浸模式（主打体验）**：
   - 专为 9:16 短剧画幅设计；
   - **主窗口支持自由缩放调整**（默认提供 450×800 推荐视窗，但绝不强制锁定系统窗体）；
   - 视频显示区域使用 `object-fit: contain` 居中展示，两侧留白区域用于渐变背景或抽屉展开，避免画面拉伸变形。
2. **宽屏剧场模式**：
   - 适合横屏短剧或大屏常规浏览；
   - 采用“左侧视频播放区（自适应最大化） + 右侧常驻选集面板/剧目详情”的双列布局。
3. **独立置顶摸鱼小窗 (Always on Top)**：
   - 独立管理的轻量无边框子窗口（非混淆的浏览器原生 PiP）；
   - 与主窗口共享单一播放会话（切换小窗时主窗口暂停，小窗接力续播，绝不双实例并发播放）；
   - 支持记忆小窗位置、尺寸与半透明度调节。

| **鼠标滚轮** | **切集** (上一集/下一集，防抖 350ms + 过滤触控板惯性) | 常规页面上下滚动 | 常规页面上下滚动 | 联想列表滚动 |

### 4.3 性能指标客观化
- 摒弃虚夸的“0 延迟秒开”口号；
- 建立工程化可度量指标：
  - 在标准宽带网络环境下，预加载命中时下一集首帧渲染延迟 **P95 < 1.0s**；
  - 换集 UI 响应时间 **< 50ms**；
  - 内存占用控制在标准 Electron 单窗口合理阈值（Idle < 150MB, Playing < 350MB）。

## 6. 五阶段路线图与准入准出决策门槛 (Milestones & Go/No-Go Gates)

```
[阶段 0: 可行性验证] ──(通过决策门槛)──> [阶段 1: 工程底座搭建] ──> [阶段 2: 内容浏览 MVP]
                                                                        │
[阶段 4: 发行打包构建] <──────────────── [阶段 3: 播放与桌面体验] <──────┘
```

### 阶段 0：可行性验证 (PoC & Feasibility Gate) —— 阻塞项
- **验证项目与准入条件**：
  1. **SDK 初始化**：在 macOS (Apple Silicon/Intel) 及 Windows 下均能正确加载本地 Wasm；
  2. **发现与搜索**：推荐列表、分类翻页、搜索联想词数据结构解析正常；
  3. **媒体模型解析**：针对合法授权/测试媒体，摸清 `resolvePlayback` 返回的具体流结构（MP4/HLS/DASH、Protected 字段、KeyMaterial 格式）；
  4. **播放通路决策 (Go / No-Go)**：
     - 测试普通流的直接播放；
     - 测试受保护流在 Web EME ClearKey 下的可行性与限制；
     - 若 Web 原生通路受限，评估外部轻量解封装管道（如集成 mpv 桥接）作为备选；
  5. **频控边界实测**：量化 `ANONYMOUS_LIMITED` 触发频次与 `resetDevice` 的实际成功率。
- **决策输出**：输出《阶段 0 可行性验证报告》，确定 Media Engine 的最终落地形态。

### 阶段 1：工程底座搭建 (Engineering Foundation)
- 初始化 Electron + Vite + React 19 + TypeScript + Tailwind CSS 脚手架；
- 封装安全安全的 Typed IPC 通道（`window.electronAPI`）；
- 集成 `vendor/openhongguo` SDK Adapter；
- 实现本地 JSON Store 原子化持久层。

### 阶段 2：内容浏览 MVP (Discovery & Browse MVP)
- 实现首页发现流、推荐频道切换、无限滚动；
- 实现搜索框轮播热词、输入实时联想词与热榜面板；
- 实现短剧详情页与 1~100 集网格选集抽屉；
- **关键保障**：本阶段即使底层播放处于故障降级，整个内容浏览、分类筛选、收藏管理依然能 100% 独立稳定运行。

### 阶段 3：播放与桌面专属体验 (Playback & Desktop Features)
- 集成阶段 0 决策后的 Media Engine；
- 沉浸式竖屏与剧场模式切换；
- 独立置顶摸鱼小窗；
- 键盘快捷键监听与触控板惯性过滤；
- 播放历史秒级断点续播与连播预加载优化。

### 阶段 4：跨平台构建与发行 (Packaging & Release)
- 配置 `electron-builder`（Windows NSIS/Portable、macOS DMG/zip）；
- 配置 `asarUnpack` 确保 `openhongguo.wasm` 在打包后正确定位执行；
- 编写端到端冒烟测试与系统托盘能力。
